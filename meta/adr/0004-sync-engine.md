# ADR-0004: Sync-движок — outbox, идемпотентность, конфликты по version

## Контекст

Offline-first: изменения статуса/заметки должны работать без сети, надёжно
доходить до сервера и корректно разрешать конфликты. Контракт даёт
оптимистичную блокировку по `version` (`If-Match`, `409 VERSION_CONFLICT`) и
батч-эндпойнт `POST /sync`.

## Решение

- **Outbox-очередь**: локальные изменения пишутся в БД с локальной версией и статусом
  операции; UI обновляется оптимистично.
- **Фоновая синхронизация** при появлении сети:  POST /sync (батч).
- **Ретраи** с экспоненциальной задержкой; частичные сбои батча обрабатываются
  поэлементно.
- **Идемпотентность**: операции не теряются и не дублируются при перезапуске.
- **Разрешение конфликтов** по `version`: стратегии `server-wins` / `client-wins` /
  слияние заметок; выбор управляется `MOCK_CONFLICT_STRATEGY` (конфиг окружения).
  Конфликт доводится до консистентного состояния и не зацикливается.

## Последствия
  - где живёт движок (packages/data/lib/src/services/sync/...);
  - как тестируется (unit на разрешение конфликтов — ключевой фокус ревью);
  - известные ограничения (например, стратегия merge только для note).
